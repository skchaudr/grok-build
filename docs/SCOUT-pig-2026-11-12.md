## What `pig` runs (Mini, verified)

1. `~/.local/bin/pig` → `~/.grok-hub/scripts/hub/pig` (symlink). Line 4: `exec .../gb grok-pi "$@"`.
2. `gb` (`~/.grok-hub/scripts/hub/gb`): `CMD[grok-pi]="${GROK_PI_ACP_BIN:-grok-pi-acp}"`, where `GROK_PI_ACP_BIN` is `~/.grok/bin/grok-pi-acp` (gb:72-84). `PAGER_BIN` is `~/.grok/bin/grok-fork` (gb:~10-16).
3. Final exec (gb:467): `env -u PAGER GROK_RESUME_CMD="grok grok-pi" ~/.grok/bin/grok-fork --agent-cmd ~/.grok/bin/grok-pi-acp`.
4. `grok-pi-acp` (`crates/codegen/xai-grok-pager-bin/src/bin/grok-pi-acp.rs`):
   - `pi_version::ensure_compatible_pi_host("pi")` (line ~96-101). Min Pi `0.99.0` (`grok_pi/pi_version.rs:23`).
   - Writes bridge extensions to temp files and passes them as `--extension` (lines ~140-330).
   - `PiRpc::spawn` runs `pi` with `--mode rpc` plus the extension flags (line ~470).
   - `PiBootstrap::load` with a 60 s timeout (line ~487).
   - Serves ACP on stdout to the pager.
5. `pi` on the Mini: `~/.local/bin/pi` → `~/.pi/agent/bin/pi`, a launcher that execs `~/.pi/agent/install/releases/$(cat current-version)/node_modules/.bin/pi`. Current version `1.5.0`. `pi --version` prints `1.5.0`.

Full chain: `pig` → `gb` → `grok-fork` (pager, TUI) → `grok-pi-acp` (ACP host) → `pi --mode rpc` (Pi core and extensions) → `cliproxy` provider (from `~/.pi/agent/settings.json`: `defaultProvider: cliproxy`, `defaultModel: gemini-3.8-flash-high`).

## Follow-up context trace (item 3)

**Verdict:** the adapter does not resend history. Each prompt sends only the new message to Pi. Context lives in the one Pi process and its session.

- `crates/codegen/pi-grok-adapter/src/pi_adapter/agent.rs:308-309`: `json!({ "type": "prompt", "message": message })`. Images and `streamingBehavior` are added, but no prior turns.
- `agent.rs:1210-1213`: steering path sends `{"type":"prompt", "message", "streamingBehavior":"steer"}`, also message-only.
- `agent.rs:34-53`: `new_session` sends `{"type":"new_session"}` only when a session is created. A follow-up does not call it.
- `agent.rs:83-114`: `load_session` checks `requested != bootstrap.state.session_id` and rebinds. A context loss would appear here only if the ACP session id changed between turns.
- `crates/codegen/xai-grok-pager-bin/src/bin/grok-pi-acp.rs` (around line 470-500): one `PiRpc::spawn` per process, then `PiBootstrap::load`. The Pi child, and therefore its history, lives as long as the `grok-pi-acp` process.
- Pi's own session store (`~/.pi/agent/sessions/`) is read by Pi, not in this repo. Not read.

Evidence it works: Mini run 2 above, and the Mini `/resume` of the 1:30 PM session restored the prior turns in the chat.

## Arrow keys in the slash menu (the core of Sab's screenshot)

**Repro (both Macs, same steps):** `pig`, type `/`, press plain Down, Down, Up.

- Mini: `Running shortcut shift+down` ×2 and `Running shortcut shift+up` printed in chat. The highlight stayed on `/model` (the menu did not move).
- sab-air (via `ssh -t sab-mini@sab-air` in Rex, then `pig`): `Running shortcut shift+down` ×2 printed. The highlight stayed on the top item. The Up press printed no `shift+up` line in my test. Unexplained (see open items).

**(a) Bytes from the terminal (verified).** Rex pane running `/bin/cat -v`, keys sent with `rex send-key`:
- Mini: `TERM=xterm-256color TERM_PROGRAM=rex COLORTERM=truecolor`; Down `^[[B`, Up `^[[A`, shift+Down `^[[1;2B`.
- sab-air (over ssh): `TERM=xterm-256color TERM_PROGRAM= COLORTERM=` (ssh drops it); bytes identical.
- Conclusion: plain arrows are sent as plain CSI sequences. Not a terminal encoding problem. No kitty or modifyOtherKeys in play for these keys.

**(b) Pager decoding (verified in code, crossterm behaviour assumed).** Plain Down arrives as `KeyCode::Down` with `KeyModifiers::NONE`. `KeyboardNormalizer::rescue` only upgrades Backspace/Delete (`crates/codegen/xai-grok-pager-render/src/input/keyboard_normalizer.rs:94-120`), so it does not add SHIFT to arrows. Not the cause.

**(c) Path to the shortcut manager (verified).**
1. `@osolmaz/pi-workflows` (0.17.7, in `settings.json` packages on both Macs) registers `shift+up` and `shift+down` by default (`~/.pi/agent/npm/node_modules/@osolmaz/pi-workflows/src/extension/shortcuts.ts:20-21`; registration `src/extension/index.ts:635-648`). No `~/.config/pi-workflows/shortcuts.json` on either Mac, so the defaults apply.
2. Pi sends the keys to the pager as `pi/ui/shortcut_dispatch` (`extension_shortcuts.rs` set by `pi_shortcuts`; the pager's `set_shortcuts` at `extension_shortcuts.rs:~106`).
3. Pager match: `route_pi_input` (`crates/codegen/xai-grok-pager/src/app/app_view.rs:2272`) calls `pi_shortcuts.match_key(key)` (`app_view.rs:2307`), which runs `key_id_matches_event` (`extension_shortcuts.rs:136-150`, `:248`).
4. On a match it sends `pi/ui/shortcut_dispatch` with the key id (`app_view.rs:2313`).
5. Adapter turns that into the hidden prompt `__pi_shortcut_dispatch` (`crates/codegen/pi-grok-adapter/src/pi_adapter/agent.rs:888-906`; command constant `pi_adapter.rs:642`).
6. Extension: `extensions/pi-grok-shortcut-manager/index.ts:30` (`registerCommand("__pi_shortcut_dispatch")`) and `index.ts:40` (`dispatchByKeyId`). `dispatch.ts:60-64` `dispatchByKeyId` runs `runHandler` with no modifier check. `dispatch.ts:24` prints `Running shortcut ${key}` before the handler runs.

**(d) Why the slash menu does not consume them first (verified).**
- `route_pi_input` runs at `app_view.rs:2391`, before the menu's arrow handling (`handle_menu_nav` at `app_view.rs:3793`, and `:4133`). If `route_pi_input` returns `Some`, the menu never sees the key. It returns `Some` on any registry match (`app_view.rs:2307-2315`).
- **Root cause: `key_id_matches_event` ignores SHIFT for named keys.** Lines 301-303 remove SHIFT before comparing modifiers. Lines 312-313 then match arrows on `event.code` alone (`"up" => event.code == KeyCode::Up`). Nothing checks the event's SHIFT bit for arrows, so `shift+up` and `shift+down` match a plain Up and Down.
- The Char branch does check SHIFT (`extension_shortcuts.rs:~318-327`). Only the named-key branch is wrong.

**Smallest fix (not applied, read-only scout).** In `crates/codegen/xai-grok-pager/src/app/extension_shortcuts.rs`, after the modifier check at line 303 and before `// Check the key itself` at line 305, add:

```rust
// Named keys (arrows, Enter, F-keys) have no shifted glyph, so SHIFT must match exactly.
if !matches!(event.code, KeyCode::Char(_))
    && event.modifiers.contains(KeyModifiers::SHIFT) != required_mods.contains(KeyModifiers::SHIFT)
{
    return false;
}
```

Add a unit test next to `match_ctrl_shift_combo` (around line 435): `key_id_matches_event("shift+up", &KeyEvent::new(KeyCode::Up, KeyModifiers::NONE))` is false; with `KeyModifiers::SHIFT` it is true; `"up"` with NONE is true.

Second layer (optional, not needed for the fix): `dispatch.ts:60-64` trusts the key id from the pager. A modifier check there would also stop a mismatched key, but the pager fix is the one that matters.

**Side effect to know:** once the fix ships, a true Shift+Up or Shift+Down while the slash menu is open still goes to the workflow scroll shortcut. That is the intended binding, not a regression.
